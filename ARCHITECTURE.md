# Architecture and isolation rules

The app is built from independent feature modules. A change inside one module
must not be able to affect another. Follow these rules when editing.

## Layout

| Concern | Source |
|---|---|
| Design tokens | `src/css/variables.css` |
| Base / components | `src/css/base.css`, `src/css/components.css` |
| NFC / Wi-Fi / lock modals, link-type switcher | `src/css/modals.css` |
| Onboarding tour (self-contained) | `src/css/onboarding.css`, `src/js/core/onboarding.js` |
| Search dropdown | `src/css/search-dropdown.css` |
| Toasts | `src/css/toast.css` |
| Templates (the only hand-edited HTML) | `src/templates/app-index.html`, `src/templates/web-index.html` |

`index.html` (web) and `android-app/app/src/main/assets/**` are GENERATED by
`python scripts/build_and_sync.py`. Never edit them by hand.

## Rules

1. One feature, one CSS file, one JS file. Every selector in a feature file is
   prefixed with the feature name (`.onboarding-*`, `.wifi-*`, `.nfc-*`).
2. A modal layer that is closed must be inert. Never force `visibility: visible`
   or `pointer-events: auto` on a descendant of an overlay outside its
   `.active` state; use `inherit` instead. Otherwise an invisible child sits on
   top of the page and swallows taps (this caused the "dead buttons" bug).
3. Each button is bound in exactly one place. `onboarding.js` does not bind the
   help button; `app-main.js` / `web-main.js` do.
4. Modules communicate only through `window.*` entry points
   (`openOnboardingModal`, `closeOnboardingModal`, `AppModes`, ...), never by
   reaching into another module's DOM.

## Regression test

```
python scripts/build_and_sync.py
node tests/ui_smoke.mjs            # APK bundle
node tests/ui_smoke.mjs index.html # web build (optional)
```

The smoke test fails if any visible control is covered by another element while
all modals are closed, if a closed overlay is not isolated, or if a JS exception
is thrown. Run it before every commit.
